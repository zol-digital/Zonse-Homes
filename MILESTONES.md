## Phase 6 — Moderation, trust, and safety

**Status: IN PROGRESS — FIRST APPROVED INCREMENT VERIFIED COMPLETE; Phase 6 is not complete.**

**First increment — pre-publication listing moderation and audit trail — VERIFIED COMPLETE.** Existing listing states already represented drafts, pending review, published, changes requested, rejected, and advertiser-paused listings; public discovery already filtered strictly to `published`. Added a distinct `moderator` assigned role and additive Alembic revision `20261102_0006`, which permits that role and creates a moderation action log with actor/listing references, action, required reason, prior/new statuses, optional private notes, and timestamp. Moderators and administrators can retrieve only `pending_review` submissions and approve, reject, or request changes. Each action requires a reason and writes the listing transition and audit row atomically. Audit-log reading is administrator-only; no API operation edits audit records. Listing and actor deletion are restricted while audit records reference them.

The advertiser flow remains owner-scoped: submitted listings remain private; request-changes/rejected/pending statuses are returned by existing advertiser endpoints; private moderator notes are excluded from listing responses; only approval transitions a submitted listing to `published` and makes it discoverable. Hide/remove endpoints and their lifecycle workflows were intentionally not added in this increment.

Verification: baseline Python 3.11.9 suite passed (235 tests). Focused moderation, identity-role, and migration tests passed (34). Final `py -3.11 -m pytest -q` passed (239 tests, 142 dependency warnings). Revision `20261102_0006` upgraded a fresh, isolated PostgreSQL 15 database; the moderator role and audit-row schema were exercised; `alembic check` reported no pending operations. OpenAPI tests confirmed the approved endpoints and absence of hide/remove routes. The isolated database container was stopped after verification. SQLite-backed API tests and PostgreSQL migration/schema checks were used; no shared or production database was accessed.

**Second increment — structured private listing reports, rate limits, and report review — VERIFIED COMPLETE.** Added anonymous/authenticated reporting for published listings using the seven PRD schema reason codes, optional validated descriptions, private report records, generic acknowledgement, duplicate-report protection, and moderator/admin report review. Reports do not change listing or advertiser status. The review queue and review actions are server-side role protected; review reasons are required, optional moderator notes remain private, and review actions link to the existing moderation audit log. Raw reporter IPs are not stored; a keyed HMAC digest supports abuse controls. Rolling limits are three reports per account and ten per source IP per 24 hours, with the IP limit applying to authenticated reporters too. PostgreSQL transaction advisory locks serialize checks across application workers sharing the database. Production requires a dedicated 32-byte `REPORT_IP_HASH_SECRET`; deployments behind proxies must configure trusted proxy handling so the framework supplies the real client IP.

Verification: Python 3.11.9 baseline suite passed (239 tests, 142 warnings); focused report, moderation, migration, identity, and configuration tests passed (68 tests, 20 warnings); final `py -3.11 -m pytest -q` passed (254 tests, 155 warnings). A disposable PostgreSQL 16 container applied all migrations through `20261102_0008`; `alembic current` reported that head and `alembic check` found no schema drift. Offline migration SQL, the single-head migration history, OpenAPI route/reason-code/privacy checks, and `git diff --check` passed. Only the disposable PostgreSQL container was stopped; no shared or production database was accessed.
